# Открытая платформа камер

**Open Camera Platform** — локальная open-source веб-панель для совместимых ONVIF/RTSP-камер без обязательной подписки на облачное хранилище производителя. Выпуск **v0.4.0** предназначен для запуска на собственном компьютере, NAS или мини‑ПК в той же сети, что и камеры.

В v0.4.0 конфигурация камер, локальные пользователи, архивный индекс, события, уведомления, аудит и политики записи сохраняются в локальной папке `data/`. Реквизиты, указанные в RTSP-адресе, извлекаются из публичной модели камеры и сохраняются отдельно в зашифрованном виде AES-256-GCM. Панель и API никогда не возвращают их в списках камер. По умолчанию ключ хранится в локальном файле `data/platform-state.key` с правами только владельца; для переносимого ключа можно задать `OCP_STORAGE_KEY` в окружении процесса и защитить его средствами операционной системы.

> Видеопоток и архив остаются на узле, который контролирует владелец. Проект не создаёт публичное P2P-подключение к камере и не отправляет видео в сторонний сервис.

## Что реализовано

| Блок | Доступные возможности | Статус |
| --- | --- | --- |
| Локальный доступ | Первый владелец, локальные роли `owner`, `admin`, `viewer`, сессионная cookie с флагами `HttpOnly` и `SameSite=Strict`, проверка прав API | Реализовано |
| Камеры | Регистрация ONVIF/RTSP-устройств, проверка локальных адресов, поиск ONVIF через WS-Discovery в локальной сети | Реализовано |
| Многокамерная панель | Русскоязычная сетка карточек, статусы, пустые состояния, управляющие действия для владельца и администратора | Реализовано |
| Живой просмотр | Запуск локального HLS-потока из RTSP без shell-интерпретатора, защищённая выдача плейлиста и сегментов | Реализовано |
| Снимки | Единичный JPEG-снимок из RTSP через локальный `ffmpeg`, защищённая отдача снимка | Реализовано |
| Запись и архив | Сегментный план записи, непрерывные/плановые/событийные правила, индекс архива, показатели объёма и явное применение политики хранения | Реализовано как локальное ядро |
| События | Нормализация событий движения, локальный журнал и создание локальных уведомлений | Реализовано |
| Контроль действий | Аудит настройки владельца, входов, камер, потоков, снимков и очистки архива | Реализовано |
| PTZ | Безопасная валидация направлений и скоростей команд | Реализовано как ядро команды |
| Удалённый доступ | Проверка конфигураций только для VPN либо HTTPS-шлюза; прямое раскрытие RTSP запрещено | Реализовано как безопасная модель |

## Быстрый запуск

Требуется **Node.js 22 или новее**. Для реального HLS-просмотра, записи и снимков дополнительно установите `ffmpeg` на тот же локальный узел, где будет запущена платформа.

```bash
git clone https://github.com/KiTaUc/open-camera-platform.git
cd open-camera-platform
npm test
npm start
```

Откройте `http://localhost:8787`. При первом запуске панель предложит создать единственного стартового владельца. Пароль должен содержать не менее 12 символов. После входа владелец может создавать роли через защищённый API; секреты и реальные адреса камер не следует размещать в issue, примерах или коммитах.

## Рабочий сценарий

1. Разместите локальный узел рядом с камерами: в домашней сети, на NAS или мини‑ПК.
2. Откройте панель и создайте владельца. Не используйте пароль от камеры как пароль панели.
3. Для ONVIF-устройств выполните локальный поиск либо добавьте службу вручную. Для живого просмотра и снимков укажите **RTSP-адрес профиля** камеры.
4. Владелец или администратор может запустить HLS и получить снимок. Наблюдатель получает только права просмотра разрешённых данных.
5. Настройте правило записи для каждой RTSP-камеры прямо в панели: **непрерывное**, **по расписанию** или **по событию**. Локальная служба оценивает первые два режима каждые 30 секунд; событийный режим продлевает запись на заданное число секунд после принятого события.
6. Перед очисткой архива явно укажите дату или лимит и подтвердите действие флажком. Подходящие локальные файлы удаляются без восстановления, а действие попадает в аудит.

## Совместимость и границы

Проект рассчитан на камеры, которые открывают стандартный ONVIF- или RTSP-интерфейс в доступной сети. Устройства, работающие исключительно через закрытое P2P-облако производителя, не предоставляющие ONVIF/RTSP либо требующие неподдерживаемый кодек, не могут быть гарантированно подключены.

Встроенный HTML-плеер использует HLS-плейлист. Поддержка HLS зависит от браузера; если браузер не воспроизводит плейлист напрямую, используйте совместимый локальный клиент или подключите HLS-совместимый проигрыватель в дальнейшей интеграции.

## Безопасность

| Правило | Причина |
| --- | --- |
| Не публикуйте RTSP-порт камеры в интернет | Прямой RTSP не является безопасным способом удалённого доступа. |
| Используйте VPN или HTTPS-шлюз | В модели проекта эти способы допустимы для внешнего доступа; прямой RTSP отклоняется. |
| Создавайте отдельные роли | Наблюдателю не требуется право добавлять камеры, запускать запись или очищать архив. |
| Ограничивайте локальную сеть | Адреса за пределами частной сети по умолчанию отклоняются при регистрации камеры. |
| Храните `ffmpeg` и архив на контролируемом узле | Реальная запись и снимки выполняются именно там, где запущен сервис. |

## Важные ограничения текущего выпуска

Платформа уже предоставляет сквозной безопасный локальный путь для управления, просмотра, событий и хранения, однако она **не является заменой драйвера камеры** и не обходится без реального RTSP/ONVIF-интерфейса устройства. Автоматические проверки не подключаются к физическим камерам и не могут подтвердить конкретную реализацию ONVIF производителя.

Состояние текущего эталонного сервиса хранится в памяти процесса: список камер, пользователей, политик записи, архивный индекс, события и аудит очищаются после перезапуска. Для постоянного использования на домашнем сервере следующий обязательный этап — подключение защищённого локального хранилища конфигурации и ключей. До этого не следует рассчитывать на процесс как на единственный долговременный реестр архива или пользователей.

Учётные данные камеры не передаются через форму панели и не включаются в примеры. Если конкретная камера требует аутентификацию в RTSP, безопасное локальное хранение её реквизитов должно быть реализовано отдельно до промышленного использования.

## Проверка качества

```bash
npm test
npm run check
```

Набор содержит **36 автоматических проверок**: валидация камер, архив, роли, сессии, аудит, ONVIF-поиск, планы записи, сквозные непрерывные/плановые/событийные политики, HLS, PTZ, события, уведомления, снимки и защищённые серверные маршруты. Тестовый режим не запускает `ffmpeg` и не открывает сетевое соединение с камерой.
